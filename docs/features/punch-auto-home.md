# 打刻画面の自動復帰（PUNCH-AUTO-HOME）

2026-11-21 ユーザー指示。共用の施設端末で、前の人の打刻画面を次の人が使わないようにする。

## 経緯

2026-11-20 ミュゲ春木。前の人（14:39 出勤）が打刻画面を開いたままにしていた画面で、15:03 に別の人が退勤を押し、前の人の退勤として記録された（10秒後に本人の退勤）。
そのため 17時以降の退勤が無く、保存食と夕方の温度が誰にも聞かれなかった（月次書類は閉めの人の退勤で聞く。`monthly-docs.md`）。
打刻した後は従来から1.5秒で一覧へ戻っていたが、**打刻せずに開いたままの画面には戻す仕組みが無かった**。

## 動き

- 打刻（出勤・退勤・休憩開始・休憩終了・施設変更）が終わったら、打刻完了を見せて `PUNCH_AUTO_HOME_MS`（5000）後に一覧へ戻す。打刻完了の表示中に触れても延ばさない。
- 打刻画面を開いたまま何も押さなければ、最後に触れた・入力した時刻から `PUNCH_IDLE_HOME_MS`（60000）で一覧へ戻す。
- 次の間は戻さず、終わった時点から数え直す（`punchHomeBlockReason()`）:
  打刻の端末保存中・有給の確認待ち（`_punchSaving` / `_plChecking`。月次書類の確認画面の回答待ちを含む）、保存の通信中（`savingCount`）、有給申請・移動距離の送信中、
  施設変更の確認、有給申請・書類・移動距離の入力画面、画面全体を覆う確認画面・お知らせ・ダイアログ（`_appOverlayOpen()`。朝の温度など `.mdoc-ov` を含む）、文字の入力中。
  出勤先の選択（select）だけでは止めない。
- 打刻完了の表示中は、打刻ボタンに加えて下の申請・カード類（修正申請・有給申請・移動距離・今月の打刻状況）も出さない（本日の打刻履歴は出す）。表示中に次の人が前の人の申請を開いて自動復帰を止めないため。
- 戻すときは「← もどる」と同じ `goHome()`。★ 役割トークン（スタッフ昇格）は「もどる」と同じく戻さない（今回の変更で扱いは変えていない）。前の人の名前・PIN の入力値・有給申請や施設の選択・打刻結果・移動距離の申請内容を残さない。
- 0.5秒ごと（`PUNCH_HOME_TICK_MS`）に確認する。見張りは打刻画面の描画（`render` の `punchHomeWatch()`）で始まり、打刻画面を離れると止まる。

## 対象

- ★ 端末キューを使う打刻（`punchOutboxEnabled()`）の打刻画面だけ。スタッフテスト画面・管理者デモ（`staffDemoMode`）・閲覧用 URL・管理画面では動かず、従来どおり（テスト画面は打刻後1.5秒で戻る）。
- 個人のスマホでの打刻も同じ動き（打刻画面を見たまま60秒置くと一覧へ戻る。PIN の入れ直しが要る）。

## 残る弱点

- ダイアログや入力画面を開いたまま放置すると、閉じられるまで戻らない（ユーザー指示で入力中は戻さない）。閉じた人には前の人の打刻画面が見え、そこから60秒以内なら前の人として操作できる（例: 短時間退勤の確認を出したまま立ち去る）。朝の温度の画面は `MDOC_POST_TEMP_IDLE_MS`（3分）で自動で閉じる。
- 60秒以内に次の人が来た場合は、前の人の打刻画面が残っている（氏名は大きく表示される）。
- 個人のスマホで打刻直後に「今月の打刻状況」などを見たいときも、5秒で一覧へ戻る（打刻完了の表示中は申請・カード類を出さない）。

# 退勤前の賄い確認

2026-10-12 追加（ユーザー指示「賄い登録を退勤時に聞くようにしたい」→「退勤ボタンを押す前に聞いて、答えたら打刻になるように」）。

## 動き

- 会社の機能フラグ `meals` が true の会社だけ（穂乃味）。マンテールは無効で、この文書の画面・列はすべて出さない（`docs/features/multitenant.md`「機能フラグ」）。

- 「賄い 要」（`mealRequired`）のスタッフが**退勤ボタンを押すと、打刻の前に**「◯月◯日、賄いを食べましたか？」を出す。
  - 「はい」→ 退勤を打刻し、端末保存が成功した後にその日を賄い取得ありにして `tc5_meals/{社員番号}` へ保存（`mealSaveEntry` と同じ経路・同じ形）。
  - 「いいえ」→ 退勤を打刻する。賄いは書かない。
  - 「退勤をやめる」→ 何もしない（打刻しない）。枠の外のタップでは閉じない（誤タップで打刻しない）。
- 打刻時刻は退勤ボタンを押した時刻（従来どおり）。
- 短時間退勤の警告（5分・10分未満）が出る場合は、警告 → 賄いの質問 → 打刻 の順。月次書類の確認（ミュゲの泉）がある場合は、賄い → 月次書類 → 打刻。
- 実装: `index.html` の `MEAL-CLOCKOUT` ブロック（`mealClockOutNeed` / `mealClockOutModal` / `mealClockOutThenPunch` / `mealClockOutCommit`）。
  `doPunch` は `_execPunch` を直接呼ばず `mealClockOutThenPunch` を通す。回答は `_execPunch(type,d,meal)` の第3引数で渡し、⑥で記録する。

## 不変条件（★）

- ★ 賄いの記録は退勤の**端末保存が成功した後**だけ書く。退勤をやめた・有給日で止まった・月次書類で取り消した・保存失敗のときは書かない。
- ★ 聞けないとき（賄い不要・社員番号なし/不正・編集不可の月・その日が既に取得あり・閲覧用）は**聞かずに従来どおり打刻する**（打刻を止めない）。
- ★ 賄いデータ未取得（`mealsLoaded` 偽）でも聞く（2026-10-15。春木でPIN直後に退勤すると質問が出なかった件。
  賄いデータは役割トークンの確立後に読むため、PIN入力の直後は未取得のことがある）。未取得の間は「その日が既に取得あり」を判定できず、取得ありの日でも聞くことがある（「はい」は同じ値を書くだけ、「いいえ」は何も書かない）。
- ★ 退勤時の「はい」は `tc5_meals/{eid}` の丸ごと PUT（`mealSaveEntry`）を使わず、`mealClockOutWrite` が **その日の1件だけを PATCH**（`{staffId, staffName, "dates/{日付}":{taken,updatedAt}}`）で足す。賄いデータ未取得でも他の日は消えない。
  書き込みには役割トークン（`r` が `s`/`a`）が要るので `afterElevation()` を待ってから送る。失敗したら「退勤の打刻は完了しています」と管理者へ伝えるよう知らせる。
- ★ 送った「はい」は `_mealCoPending` に持ち、`tc5_meals` を取り直したとき（`ensureStaffScopedData` / `ensureAdminData` / 賄い一覧の定期取得）に応答に無ければ `mealClockOutMergePending()` で足し戻す（保存より古い応答で消さない。後の全体PUTで消えないように）。
- ★ 答えるまでに同じ人の退勤が手元に届いていたら打刻しない（二重打刻防止）。画面を離れていたら打刻しない。
- 回帰テスト: `node scripts/test-meal-clockout.js`（`doPunch` / `_execPunch` の結線も検証）。

## 打刻画面の賄い入力欄・月初確認は非表示（2026-10-12 ユーザー指示）

- 退勤時の質問で毎日登録するため、打刻画面の「🍚 賄い入力」カードと「◯月の賄い入力は済んでいますか？」（月初確認）を出さない。
  `index.html` の `MEAL_PUNCH_CARD_VISIBLE=false` で切り替える（処理・データは残す。`true` に戻せば打刻画面には再表示される。管理画面の月初確認は下記のとおり削除済み）。
- ★ 打刻画面での `tc5_meals` の読み込みは止めない（退勤時の質問の判定・保存に必要）。
- 本人が後から賄いを直す画面は無くなる。管理画面の賄い一覧（「CSV出力」タブ内）は閲覧のみ。

## 管理画面：月初確認の削除・賄いCSVの移設（2026-10-12 ユーザー指示）

- 「賄い一覧」タブから「確認」列・「◯月分 月初確認：」の集計・説明文・CSV出力ボタンを削除した。
- 賄いは「CSV出力」タブの**日次CSV**（最後の列「賄い」：取得ありの日は `1`）と**月次CSV**（最後の列「賄い回数」）に入れる。
  画面のプレビューにも同じ列（日次「賄い」●・月次「賄い回数」）を出す。単独の「賄いCSV」は廃止（2026-10-12 ユーザー指示）。
- 引き当ては社員番号（`mealTakenByName` / `mealCountByName`）。社員番号が無いスタッフは 0 になる。
  日次CSVは打刻のある日だけの行なので、打刻の無い日の賄い（旧・賄い入力欄で登録した分など）は月次の「賄い回数」にだけ数えられる。
- ★ 賄いデータ未取得（`mealsLoaded` 偽）のときは日次・月次CSVを出力しない（全員0のCSVを正しい集計として渡さない）。
- 労務士画面の「この月の賄い回数」とそのCSVの「賄い回数」列は変更していない。

## 管理画面：賄い一覧を「CSV出力」タブへ統合・スタッフ別サマリーを非表示（2026-10-12 ユーザー指示）

- 上部メニューの「賄い一覧」タブを廃止し、「CSV出力」タブの勤怠精査ステータスの下に「🍚 賄い一覧を表示」ボタンを置いた。
  押すと賄い一覧（賄い不要のスタッフも表示・日別の取得状況・合計）が開き、ボタンは「賄い一覧を非表示」になる。初期は閉じる（`mealListOpen=false`。同じセッションの間は開閉状態を保つ）。
  開閉は `render()` で描き直すだけで、ページの再読み込みはしない。開いたときは開閉ボタンを固定の管理者バーのすぐ下へスクロールする（閉じるのにスクロール不要）。
- 賄い一覧の表示月は「CSV出力」の対象月（`selMonth`）と同じ。賄い一覧側の月選択欄は無い（2026-10-12 ユーザー指示で統一）。
  月を変えても `tc5_meals` は取り直さない（全月分を持っている）。勤怠精査の対象月（`reviewMonth`）は別のまま変わらない。
- ★ 閉じている間は賄い一覧を描画せず、`tc5_meals` の10秒ポーリングもしない。賄い一覧のための打刻の範囲取得は無い（表示月の `selMonth` は既定で取得済み）。
- ★ 管理画面は `tc5_meal_confirmations`（月初確認）を定期取得しない。管理画面に使う箇所が無い（参照は職員の打刻画面の月初確認バナーだけで、`ensureStaffScopedData` が読む）。管理画面の初回取得（`ensureAdminData`）の1回は残す（`mealsLoaded` の判定に含まれるため）。
  日次・月次CSVに要る賄いデータは、従来どおり管理画面の初回取得（`ensureAdminData`）で読む。
- 旧タブ名で `setTab("meals")` が呼ばれた場合は「CSV出力」タブで賄い一覧を開いた状態にする。
- 「CSV出力」タブの「スタッフ別サマリー」は `EXPORT_STAFF_SUMMARY_VISIBLE=false` で非表示（`true` に戻せば再表示）。非表示の間は集計もしない。CSV出力と勤怠精査には影響しない。

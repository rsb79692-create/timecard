## 打刻時の顔撮影（スタッフ別ON/OFF・2026-09-12）

スタッフ管理モーダルの「打刻時の顔撮影」をONにしたスタッフだけ、**出勤・退勤**の打刻時に
インカメラで1枚撮影する。実装は `index.html` の `// ===== FACECAM-BEGIN/END =====` ブロック。

### 目的は心理的な不正抑止だけである

★ **本人確認ではない。** したがって次を行わない。行える実装にもしない。

・顔認証・本人判定をしない
・写真をサーバへ送らない（`fetch` / `authFetch` を呼ばない）
・端末へ保存しない（localStorage / IndexedDB / Cache Storage へ書かない）
・**Blob も dataURL も作らない**（＝残せる形のデータを一切生成しない）
・管理画面から写真を見る導線を作らない

撮影は「キャンバスへ1枚 `drawImage` した時点」で完了し、`finally` でキャンバスを消し、
大きさを 0 にし、`video.srcObject` を外し、カメラのトラックを停止する。
`scripts/test-face-photo.js` がこの破棄と、禁止APIへ触れていないことを機械的に固定している。

### 既定は OFF（フェイルセーフ）

★ 判定は `facePhoto === true` のときだけ ON とする。
**未設定・null・`false`・文字列 `"true"`・数値 1 はすべて OFF。**

・既存スタッフは全員 OFF（`tc5_staff` に `facePhoto` を持たないため）
・新規登録もチェックを入れなければ OFF
・保存時に `true` を書くのはチェックONの分岐だけ。**勝手に ON へ移行する処理を作ってはならない**
・回帰テストが `facePhoto=true` の出現箇所を2か所に固定している（自動ONの混入を検出する）

### 打刻を止めない（★ここを崩してはならない）

呼び出し位置は `_execPunch` の中、**端末保存（IndexedDB）が成功して画面が打刻済みになった後**、
かつ **`punchOutboxFlush("punch")` より前**。`await` しない。

・カメラの起動を待って打刻を遅らせない（即時打刻を壊さない）
・権限拒否・カメラ占有・非対応でも例外を投げず、打刻はそのまま成立する
・端末保存に失敗した打刻では撮影しない（`if(!_saved) return;` が先にある）
・オフラインでも動く（通信を一切しない）

### 撮影の開示と表示（★ ここを崩してはならない）

**開示は画面の「上端」に固定ストリップで出す**（`id="facecam-strip"`）。
文言は撮影の成否で差し替える（DOM を直接書き替えるので `render()` を待たない）。

★★ **下端にも本文にも置けない。** 2026-09-12 に両方を試して却下した経緯があるので繰り返さないこと。
・**下端**は更新バナー（`bottom:0` / z-index 9998。打刻端末では誰も押さないので**出たままになる**）と
　打刻時刻に挟まれて、320px 幅（可視高 約460px）では安全な位置が存在しない。
・**本文（流し込み）**は、打刻完了ブロック自体が可視高を超えるため、未送信打刻バナー・
　お知らせ・氏名の折返しのいずれかで**開示文が画面外へ押し出される**。1.5秒で画面が戻るので
　スクロールして読むこともできない。
・**上端**なら、覆うのは「← もどる」だけである（打刻直後に押す導線ではない）。

**プレビュー（映像）は余裕があるときだけ見せる。**
・幅 264px（`max-width:calc(100vw - 24px)`）、映像 64x48 と文言を横並びにして高さ約64px
・`faceCamHasRoom()` が「**打刻時刻の行**（`id="punch-time-line"`）の下端＋12px より下に収まる」と
　判断したときだけ表示する。基準が取れないときは**出さない**（判定できないなら出さない側へ倒す）
・収まらないときは 1x1・`opacity:0.01` の箱として置く（映像を再生できないと撮影できない端末が
　あるため要素自体は残す）。視覚的には何も出ず、開示は上端のストリップが担う
・更新バナーが出ているときは、その高さぶん持ち上げる（`faceCamBottomPx()`）。
　z-index を上げる対応は不可（`pointer-events:none` なので見えないバナーのボタンが押せてしまう）
・表示は 1300ms（画面遷移 1500ms より短く）、上限 2600ms。`punchTimer` と `goHome()` からも閉じる
・撮影が固まったまま（権限ダイアログ未応答）でも、15秒で再入ガードを解く
　（解かないと、その端末では以後一切撮影されなくなる）

### 撮影の瞬間の演出（シャッター音・フラッシュ・2026-09-30）

「撮影された感覚が無い」という利用者の声を受けて追加した。

・`faceCamCaptureOnce` の `drawImage` の**直後**に `deps.onShot()` を1回だけ呼び、そこで音とフラッシュを出す
　（実際の撮影タイミングと演出を一致させるため）。★ `onShot` へ画像・キャンバス・映像を渡さない。
　演出の例外は握って撮影結果と破棄を変えない。撮影に失敗したときは呼ばない
・音は Web Audio でノイズ2発を合成した「カシャッ」。★ ブラウザから Android 標準のカメラ音は呼べない。
　音声ファイルを足さない（`OFFLINE_URLS` を増やさず、オフラインでも鳴る）。
　`AudioContext` は打刻直後（`faceCamAfterPunch` の先頭）で準備し、自動再生の制限で鳴らない状態を避ける。
　端末の**メディア音量**で鳴る（マナーモードでも鳴る場合がある）
・フラッシュは全画面の白（`#facecam-flash`・z-index 10000・`pointer-events:none`）を約0.2秒で消す。
　★ 打刻完了の表示は1.5秒しかないので、打刻時刻が透けて読める不透明度 0.7 に抑える
　（視差効果を減らす設定の端末では 0.3）。`faceCamClose()` でも消す
・音を鳴らした0.4秒後に `AudioContext` を休止する（常時起動の打刻端末で音声出力を開いたままにしない）。
　iOS はタップ操作の外で再開できず、鳴らない場合がある（未確認）
・★ 自分の撮影表示が出ていないとき（画面がホームへ戻った後に撮影が着地した等）は鳴らさず光らせない
・マイクは使わない（`audio:false` のまま）
・Android 実機での見え方（音とフラッシュのずれ・音量）は未確認（2026-09-30 時点）

### 撮影しない画面

`writePolicy !== "full"`（スタッフテスト画面）・管理者デモ・閲覧用URL・
出勤退勤以外の打刻（休憩・施設変更）では撮影しない。
表示は `#app` の外（body 直下）へ置く。`render()` で消えないようにするためであり、
`pointer-events:none` で打刻画面の操作を一切ふさがない。最大3秒で必ず閉じる。

### 既知の制限（運用で認識しておくこと）

1. **`tc5_staff` は一般スタッフでも書ける。** したがって次の2つが可能である。
   `/honomi` の `.write` が `r==='s'` を許しているため（移動距離の利用ON/OFFを
   サーバ側 `/mileage/enabled` へ置いたのと同じ問題）。
   - **対象職員が自分の `facePhoto` を消して撮影を無効化できる。**
     ★ **無効化されたことを検知する手段は無い。** この機能の唯一の目的（抑止）はその職員に対して失われる。
     「フラグを消しても得られるものは無い」と書いてはならない（2026-09-12 の監査で訂正）。
   - **第三者が他人の `facePhoto` を ON にできる**（本人が知らないうちにインカメラが起動する）。
     緩和として、撮影表示に「管理者設定により撮影しています」と必ず出している。**この文言を外してはならない。**
   ★ それでも `tc5_staff` に置いているのは、**打刻をオフラインで成立させるため**である。
   サーバ側に置くと、打刻のたびに Vercel へ問い合わせないとON/OFFが分からず、
   通信断で打刻できない（または撮影の可否を推測する）ことになる。
   将来サーバ側へ移す場合も、**打刻のたびに問い合わせる形にしてはならない**
   （起動時に取得してメモリへ保持し、取得できなければ OFF とする形に限る）。
   この判断を読み替える前に、必ず打刻のオフライン要件を確認すること。
2. **IndexedDB が使えない端末では打刻自体ができない**（既存の制限）。撮影の有無は無関係。
3. **カメラを許可していない端末では撮影されない。** 打刻は成立するため、
   「撮影されなかった打刻」は存在しうる。撮影の有無を根拠に勤怠を否認してはならない。
4. **初回だけブラウザのカメラ許可ダイアログが出る。** 打刻後の画面遷移（1.5秒）をまたいで
   ダイアログが残ることがある。★ ONにする前に、管理者がその端末で1度カメラを許可しておくこと。
   許可しないまま運用すると、ONのスタッフが打刻するたびにダイアログが出る。
5. **iOS はホーム画面へ追加した PWA でも `getUserMedia` が使える**（iOS 14.3 以降）。
   ただし HTTPS 必須。本番は GitHub Pages（HTTPS）なので満たしている。

### ONにする前にやること（運用手順）

1. **対象職員へ事前に周知する。** 写真を残さない実装でも、カメラが起動し顔画像を一時的に取得する。
   本人が理由を知らないまま起動する状態を作らない（撮影表示にも「管理者設定により撮影しています」と出る）。
2. **その端末でカメラを1度許可しておく。** 許可しないままONにすると、打刻のたびに
   ブラウザの許可ダイアログが出る。
3. ONにするのはスタッフ単位。既定はOFFで、管理者が明示的に入れたときだけ有効になる。

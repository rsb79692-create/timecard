# 有給の付与日 LINE通知

> **Claude Code は本書を自動では読み込まない。この機能を変更・調査するときに必ず読む。**
> 2026-11-03 追加（ユーザー指示「有給付与の通知が来るようにしてくれ。今は有給管理を開くまで分からない」）。

## 何をするか

有給管理の「付与予定（未登録）」と同じ判定で、付与日を迎えたのに付与行（`tc5_paid_leave_balances`）がまだ無いものを、
朝出勤確認と同じ LINE の宛先（`LINE_TO_ID`）へ知らせる。

| いつ | 条件 | 本文の見出し |
|---|---|---|
| 毎朝（JST） | 今日が付与日の未登録が1件以上 | `有給の付与日です（YYYY年M月D日）` |
| 毎週月曜の朝 | 付与日を過ぎて未登録・**期限内**のもの、または今日が付与日のものが1件以上 | `有給付与の登録待ち（毎週月曜のお知らせ・…）`（今日の分も同じ1通に入れる） |
| 上のどちらでもない | — | 送らない |

本文の例（付与日の朝）:

```
【穂乃味タイムカード】
有給の付与日です（2026年11月3日）

・佐藤花子　第2回（付与日 2026-11-03）
・山田太郎　第1回（付与日 2026-11-03）

管理画面の「有給管理」→「付与予定（未登録）」から登録してください。
```

- 載せるのは氏名・第n回・付与日だけ。**付与日数は載せない**（出勤日数の全履歴が要る。日数は有給管理の画面で確認して登録する）。
  社員番号・入社日・管理者用 URL も載せない。1区分30行まで（超える分は「他 N 件」）。
- 月曜のまとめでは、期限切れ（`expiresAt` < 今日）の付与回は載せず件数だけ添える（画面の説明どおり登録不要のため。
  載せると古い付与回が毎週出続ける）。社員番号の未設定・重複の人がいれば、その旨を1行添える（氏名は出さない）。
- 氏名は改行・制御文字を空白にして40文字で切る（本文の行の偽装を防ぐ）。

## 判定（★ index.html と同じにする）

- 付与日: 第n回 = 入社日 + 6 + (n−1)×12 か月（日が無い月は翌月へ繰り越す。1/31 入社 → 7/31、8/31 入社 → 3/3〔閏年は 3/2〕）。期限は2年後の前日。
  `scripts/paid-leave-notify.js` の `calcGrantSchedule` は `index.html` の `calcPaidLeaveSchedule` と同じ結果になるようにしている。
- 対象外: 退職（`status==="退職"`）・社員番号なし・社員番号の重複・入社日なし。登録済み = 同じ社員番号＋付与日の付与行がある
  （旧形式の `staffId=氏名` の行は `normalizePaidLeaveBalance` と同じく社員番号へ解決して照合）。`getPaidLeaveUnregistered` と同じ。
- ★ **どちらかを直したら両方を直す。** `node scripts/test-paid-leave-notify.js` が `index.html` の実物を抜き出して一致を検査する（入社日の形・今日・合成データ300通り）。
- 入社日は `YYYY-MM-DD` / `YYYY/MM/DD` / `YYYY.M.D` / `YYYYMMDD` を読む。時刻付きなど他の形は通知しない（件数だけログへ出す）。
- 「今日」は JST（実行時刻 + 9時間）。計算はタイムゾーンに依存しない（Actions は UTC で動く）。

## 実行

- ワークフロー `.github/workflows/paid-leave-notify.yml`。cron `40 22 * * *`（= 07:40 JST）の**1本だけ**。
  ★ **通知記録を持たない**（RTDB へ書かない・`database.rules.json` を変えない）。起動元を増やす（外部スケジューラから呼ぶ・cron を足す）と同じ日に2通になる。
  cron は1〜2時間遅れることがあるが JST の同じ日のうちに届く。取りこぼした日の分は月曜のまとめで拾う。
- 読むのは `tc5_staff` と `tc5_paid_leave_balances` だけ（GET のみ）。`tc5_paid_leave_balances` は役割トークンが要る領域なので、
  `notify-check` と同じくサービスアカウント（`FIREBASE_SERVICE_ACCOUNT_KEY`）で読む。
- Secrets は既存の `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_TO_ID` / `FIREBASE_DATABASE_URL` / `FIREBASE_SERVICE_ACCOUNT_KEY` だけ（新規なし）。
- 会社: `TENANT_ID`（未指定 = 穂乃味）。他社は `/tenants/<会社ID>` を読み、`LINE_*__<会社ID大文字>` へ送る。未設定なら止まる（穂乃味の宛先へ倒さない）。
  ワークフローは穂乃味だけを動かす。他社を動かすには `TENANT_ID` 付きのジョブと Secrets の追加が要る（人の確認が必要）。
- LINE は `X-Line-Retry-Key` 付きで送り、5xx・通信エラーは同じ key で最大3回。4xx は再送せず失敗（ジョブが赤くなる）。
- ログは件数だけ（氏名・社員番号・入社日・URL・トークンを出さない。**公開リポジトリの Actions ログ**のため）。
  dryRun の本文は、Actions 上では氏名・第n回・付与日を伏せ（付与日と回から入社日を逆算できるため）、手元の実行だけ実名で出す。

## 確認のしかた

- 回帰テスト: `node scripts/test-paid-leave-notify.js`（依存パッケージなし・送信なし・本番データ非アクセス。https は模擬）。
- ★ ワークフローは main へ入るまで Actions に出ない・cron も動かない（schedule は既定ブランチだけ）。
- 手動実行（Actions → 有給付与日 LINE通知 → Run workflow）: `dryRun` は**既定で ON**。`targetDate` で基準日を変えられる
  （月曜を指定すればまとめの内容を確認できる）。`testNotify` は Firebase を読まずにテスト文だけ送る（dryRun OFF のときは実送信）。
- 実送信の確認は人の承認を得てから行う（`AGENTS.md`「通知の検証は dryRun に限る」）。

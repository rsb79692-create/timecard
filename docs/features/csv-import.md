# CSV一括登録（施設マスター・従業員マスター）— 2026-09-29

管理者メニューの「CSV一括登録」タブから、施設CSV・従業員CSVを取り込む。**全社共通の機能**（会社ごとの分岐なし）。
コード: `index.html` の `CSVIMP`（純粋関数。`// ===== CSV一括登録（施設・従業員）: 純粋関数 BEGIN/END =====`）と `csvImp*`（画面・登録処理）。
回帰テスト: `node scripts/test-csv-import.js`（依存なし・送信なし・合成データのみ）。

## 流れ

ファイル選択 → 解析・検証 → プレビュー（登録予定／更新予定／スキップ／警告／エラーの件数と「○行目（氏名）：理由」）→「登録する」
→ **登録直前に最新を取り直して検証し直す**（確認時と内容が違えば書かずに再確認させる）→ **1回の PATCH** で書く → 取り直して確認。

- RTDB の複数パス更新（1回の PATCH）は全部成功か全部失敗なので、「20人中12人だけ登録」は起きない。
- 書くのは「新規は既存の末尾の次の添字」「更新は既存施設の補足項目のパス」だけ。**既存行を丸ごと上書きしない。**
- 同じCSVを2回取り込んでも、2回目は同名が登録済みのためスキップになり二重登録しない。

## 識別子と照合（★変えてはならない）

- **従業員の本人の識別子は氏名（姓＋名、空白なし）**。打刻（`tc5_records.staff`）・承認（`日付__氏名`）・PIN が氏名で紐付く。
  社員番号（`employeeId`）は自由項目で、**空欄・重複を許す**（警告のみ）。後からスタッフ管理画面で変えても打刻・承認・PINは別人にならない。
  ただし月別出勤日数・賄い・有給残（`staffId`）・移動距離は社員番号キーなので、既にそれらのデータがある人の番号変更は既存の編集画面と同じ注意が要る。
- **登録済みと同じ氏名の行は上書きせずスキップ**（CSV に本人を確実に特定するIDが無いため）。空白・全角半角だけが違う氏名はエラー（自動で紐付けない）。CSV内の同名は両方エラー。
- 施設は施設名が識別子（従業員の `location` は施設名の文字列）。従業員CSVの施設名は**登録済み施設との完全一致だけ**を受け付け、表記ゆれは推測で紐付けない。見つからなければエラー（施設を自動作成しない）。
- 登録済みの施設と同名の行は、CSVで空欄でない補足項目（`code` `formalName` `postalCode` `address` `tel`）だけを更新する。**施設名・`token` は変えない。** 新規施設には英数字32文字のトークンを生成する。

## 列の対応

| 従業員CSV | 保存先 | 備考 |
|---|---|---|
| 社員コード | `employeeId` | 空欄・重複は警告のみ |
| 姓・名 | `lastName` `firstName` `name`(=姓+名) | 姓は必須 |
| ふりがな | `yomiLast` `yomiFirst` `yomi` | 空白で姓よみ・名よみに分ける。必須 |
| 在籍状態 | `status` | 在籍・休職・退職。退職は退職日必須、退職以外は退職日不可 |
| 所属部署 | `dept` | マスター管理の部門と完全一致のみ（部門を一度も保存していない会社は、画面と同じ既定の部門 `DEF_DEPTS`） |
| 役職 | （取り込まない） | Timecard に項目が無い（「権限」とは別物） |
| 施設名 | `location` | 施設マスタと完全一致のみ |
| 雇用区分 | `employmentType` | 正社員・パート・アルバイト・契約社員。「社員」は「正社員」として登録（プレビューで明示） |
| 入社日・退職日 | `hireDate` `retireDate`（`YYYY/MM/DD`） | `YYYY-MM-DD` / `YYYY/MM/DD`。空欄可。1950年より前・1年以上先は**補正せず警告** |

施設CSVの状態「無効」の行は登録しない（Timecard に施設の無効状態が無いため）。

## 安全

- 書き込みは既存の管理画面と同じ経路（`authFetch` → RTDB。権限は Rules）。新しい API・鍵・Rules 変更は無い。画面は `csvImpCanWrite()`（管理者認証済み・デモ／閲覧でない・`writePolicy==="full"`）のときだけ登録できる。
- UTF-8（BOM有無）だけを受け付け、それ以外は文字化けさせずに拒否する。1MB・3000行まで。
- 先頭が `= + - @` の値（CSV injection）、制御文字、Firebase のキーに使えない文字（`. # $ [ ] /`）はエラー。
- PIN は CSV に含めない。登録後に PIN未設定の人数を表示する（以前の同名スタッフのPINが残っている人も表示する）。

## 既知の制限

- 操作ログ（誰が・いつ・何件）は残していない。管理者だけが書ける置き場所が無く、Rules の変更（honomi-board と共有。人の確認が必要）が要るため。
- 追加の添字は「登録直前に取り直した時点の末尾の次」。その直後（数百ミリ秒）に別の端末が同じ添字へ追加した場合や、別の端末が古い一覧のまま全体を保存（既存のスタッフ編集は全体 PUT）した場合は、どちらかが消えうる。登録後の取り直しで「登録前から在った行が消えていないか」を照合し、消えていれば画面で名前を示して知らせる。ETag の条件付き書き込みにはしていない（ブラウザから ETag 応答ヘッダを読めるか未確認のため）。
- 以前の同じ氏名の PIN が `tc5_pins` に残っている人は、登録は止めずに画面で知らせる（PIN の再設定を促す）。
- 穂乃味（`/honomi`）の `master/locations` は匿名でも読めるため、取り込んだ施設の補足項目（正式名称・住所・電話番号など）も同じ範囲で読める。業務上公開してよい情報であることが前提。
- 既存の Rules ではスタッフのトークン（`r:"s"`）も `tc5_staff` / `master/locations` を書ける（本機能以前からの状態）。CSV取込の画面は管理者だけに出すが、REST を直接叩く書き込みは Rules 側でしか止められない。
